# GUI

## 启动

需要 Bun >= 1.4.0。首次安装会下载 Electron。

```sh
bun install --no-save

# 独立 Web 可执行文件
bun run build:web
./dist/web/opi-web --cwd /path/to/project

# 只构建桌面应用目录，直接预览
bun run build:desktop --dir
bun run desktop

# 当前系统的桌面分发包
bun run build:desktop
```

Windows 的 Web 产物为 `dist/web/opi-web.exe`。Desktop 应用名和可执行文件名为 `opi-desktop`。分发文件位于 `dist/desktop/release/`，Linux 为 `opi-desktop.AppImage`，macOS 为 `opi-desktop.dmg`，Windows 为 NSIS 安装程序 `opi-desktop.exe`。MVP 未配置签名、macOS 公证或自动更新。三平台分别构建，不把 Linux 构建成功视为其他平台已经验证。

`bun run dev:web` 构建前端后从源码启动 Web 服务，不提供热更新。

`opi-web -h` 或 `--help` 查看参数及默认值。`-p` 是 `--port` 的简写，端口须为 0–65535 的十进制整数，`0` 表示自动分配。`--cert` 和 `--key` 必须同时指定。参数错误输出到 stderr，并以状态码 1 退出。

本仓库不提供预构建文件。两个本地构建产物都包含 SDK 和所需运行资源，不要求用户安装 Bun、Node.js 或仓库依赖。Bash、Git、语言服务器等外部工具仍按使用场景由用户安装。Desktop 不需要另外安装 `opi-web` 或 `opi`。

沿用 `~/.pi/agent` 的配置、认证和会话，支持用 `PI_CODING_AGENT_DIR` 覆盖该目录。GUI 直接读取共享 `sessions/` 下各工作区的历史，无需导入或迁移。Web 读取的是后端电脑上的数据，不是访问网页的手机或电脑的本地目录。

Web 内嵌资源使用与 CLI 相同的内容寻址缓存。输入历史与 TUI 共用 `~/.pi/cache/user-history/history.jsonl`，按工作目录隔离。

## SDK 更新日志

SDK 升级后，Desktop 和 Web 在首次打开空会话时，将新增版本日志放在聊天区顶部，不弹窗、不抢焦点。日志来自随应用打包的 SDK `CHANGELOG.md`，无需联网，不写入会话历史或模型上下文。

沿用 `~/.pi/agent/settings.json` 的 `lastChangelogVersion`，与 TUI 共享已读状态。GUI 实际展示后才记录当前版本。首次使用只建立版本基线，恢复已有消息的会话和仅启动后端不消耗提示。展示后刷新、重连、新建或切换会话不重复插入。

`collapseChangelog` 为 `true` 时只显示版本提示，点击可原地展开。默认 `false`，直接展示 Markdown 正文，也可手动收起。`quietStartup` 不隐藏更新日志。

## Desktop 卡顿诊断

桌面应用自动将发送、新建、切换和列表刷新的时间线写入 Electron 日志目录中的 `gui-timing.jsonl`。macOS 默认为 `~/Library/Logs/opi-desktop/`，其他平台为应用用户数据目录下的 `logs/`。日志异步写入，单文件达到 2 MiB 后轮转为 `gui-timing.jsonl.1`，只保留这两份。正常退出会等待日志写完，写入失败不会阻止聊天。

日志只包含操作名、会话和请求标识、推送批次、时间与成功/失败状态，不记录消息正文、附件、工作区路径或认证内容。时间字段为 Unix 毫秒。

- `main_received`：主进程收到操作。`submittedAt` 是渲染进程调用发送桥接的时间，`requestId` 关联后续请求记录。
- `backend_received`：SDK 后端收到请求。
- `user_available`：后端首次观察到当前会话状态中的新用户消息，尚未经过推送队列。`userTimestamp` 是消息时间，`sessionId` 关联发送请求。这证明消息已进入会话状态，不代表文件已经落盘。
- `user_snapshot`：主进程收到包含用户消息的会话状态。`backendSentAt` 是后端发出时间，`userTimestamp` 是其中最新用户消息的时间。`full: true` 也可能是打开旧会话时重放历史。
- `renderer_received`：渲染进程收到推送。
- `renderer_applied`：前端解码并通知状态订阅者后发出确认。`appliedAt` 是确认发出时间，不代表屏幕绘制完成。使用同一 `run`、`generation`、`deliveryId` 关联推送记录。
- `request_settled`：操作完成或失败。对于聊天请求，此阶段通常在整轮回答结束后出现，不是首条用户消息出现的时间。

发生延迟后保留这两份日志及大致发生时间，可区分桥接、后端准备、推送接收和前端处理阶段。排查首次发送时，应排除 `userTimestamp` 早于本次 `submittedAt` 的历史重放。时钟调整会影响跨进程时间差，日志不单独证明某段代码是根因。

## 悬停提示

GUI 悬停提示统一使用 Tooltip，不使用原生 `title`。提示只写动作、状态或短标签，不重复可见内容，不拼接操作说明。文件路径和模型 ID 可保留完整标识。长命令、参数和列表通过点击展开查看。图标按钮的无障碍名称与简短提示分开维护。

## GUI 设置

左栏“设置”按外观、交互、桌面 Web 访问、会话行为、自动标题、终端工具、文件工具、默认工具、网络与网页、权限与安全、子代理、代码智能、MCP、集成、终端界面分类。宽屏使用左侧纵向分类，窄屏使用顶部分类选择器。浮窗通过 Grid/Flex 和视口相对尺寸布局，切换分类时尺寸不变，长内容在右侧独立滚动。选择器复用 shadcn/ui Select，支持键盘导航。

外观、交互、桌面 Web 访问和会话行为与模块设置统一使用“保存”“放弃修改”按钮和未保存提示。切换分类保留草稿，关闭设置时检查未保存修改。外观、交互和桌面 Web 访问还提供“重新读取”，恢复默认值只修改当前页草稿。外观和交互设置不依赖活动会话，保存后直接应用，不重载 Agent，也不打断任务。桌面 Web 访问保存后需重启 Desktop。会话行为页保留自动压缩、重试、图片处理、消息队列和完整 `settings.json` 编辑入口。有未保存草稿时禁用完整配置编辑入口。外观和交互在打开设置或窗口返回前台时重新读取外部修改，不覆盖未保存草稿。

默认配置为安装目录的 `agent/defaults/gui.jsonc`，用户覆盖为 `~/.pi/agent/configs/gui.jsonc`。支持 `PI_CODING_AGENT_DIR` 改变用户目录，以及 `PI_GUI_CONFIG` 单独指定文件路径。不读取项目层。Web 编辑的是后端电脑上的配置，连接同一宿主的页面会收到保存后的设置。

| 字段 | 默认值 | 用途 |
| --- | --- | --- |
| `theme` | `"system"` | 跟随系统，也可选择 `"light"` 或 `"dark"` |
| `themeColor` | `"#007AFF"` | `#RRGGBB` 主题色，由调色板生成组件颜色 |
| `materials.enabled` | `true` | 启用磨砂材质，关闭后表面不透明并停止页面模糊 |
| `materials.desktop` | `true` | 允许 Desktop 窗口背景透明，不影响 Web |
| `fonts.ui` | `[]` | 界面与对话字体链，按优先顺序排列 |
| `fonts.code` | `[]` | 代码、路径与日志字体链，按优先顺序排列 |
| `fontSizes.ui` | `14` | 界面基准字号 |
| `fontSizes.chat` | `16` | 对话基准字号 |
| `fontSizes.code` | `14` | 代码基准字号 |
| `sendShortcut` | `"mod-enter"` | Ctrl/⌘+Enter 发送，也可选择 `"enter"` |
| `desktopWeb.enabled` | `false` | Desktop 启动时是否开启 Web 访问 |

主题色选择器提供预设色、色相/饱和度/明度滑块及 HEX 输入。调整时实时预览，释放滑块、键盘调整结束或 HEX 输入确认后保存。输入失焦也会保存合法值，非法输入不写入配置。保存冲突时撤销预览并显示错误。可单独重置主题色，恢复全部默认设置也会清除主题色覆盖。

### 磨砂与透明

“外观 → 磨砂与透明”支持按区域调整表面不透明度、页面内模糊和背景饱和度。参数实时预览，保存后写入配置，放弃修改恢复已保存值。Desktop 背景开关保存后生效，无需重启。聊天区与输入器外围共用较厚的内容画布，代码使用局部加厚填充。表面参数不改变文字透明度。

| `materials` 区域 | 用途 | 浅色不透明度 % | 深色不透明度 % | 模糊 px | 饱和度 % |
| --- | --- | --- | --- | --- | --- |
| `canvas` | 聊天主画布与输入器外围 | 88 | 92 | 32 | 100 |
| `sidebar` | 左侧栏与窄屏导航抽屉 | 72 | 86 | 24 | 110 |
| `toolbar` | 聊天顶栏 | 80 | 90 | 24 | 110 |
| `inspector` | 会话信息栏，含会话树、统计与遥测 | 86 | 90 | 24 | 110 |
| `composer` | 输入器 | 88 | 92 | 20 | 110 |
| `floating` | 菜单与浮动操作 | 86 | 86 | 24 | 110 |
| `dialog` | 弹窗外壳，小对话框整体 | 94 | 96 | 32 | 110 |
| `overlay` | 弹窗与抽屉背后的遮罩 | 32 | 32 | 4 | 100 |

每个区域可部分覆盖浅色不透明度 `opacity`（0–100）、深色不透明度 `darkOpacity`（0–100）、`blur`（0–64）和 `saturation`（0–200）。深色模式默认减少背景透色，让深色底主导工作界面。设置为跟随系统时，不透明度随系统配色自动切换。原有 `opacity` 字段只控制浅色，深色未配置时使用区域默认值。100% 不透明度表示完全遮住背景，100% 饱和度保留原色。例如：

```json
{ "materials": { "sidebar": { "opacity": 65, "darkOpacity": 92 }, "floating": { "blur": 32 } } }
```

Desktop 在 macOS 使用 vibrancy，在 Windows 11 22H2 及以上使用 Acrylic。旧 Windows 保持不透明背景。Linux 输出带透明通道的窗口，背景模糊由桌面/合成器及其规则决定，应用不配置合成器。Linux 的透明、缩放和窗口装饰效果依赖实际桌面环境，需要在目标环境验证。

macOS 的原生磨砂与 CSS `backdrop-filter` 叠加会出现闪烁或画面割裂。为兼容这一渲染缺陷，启用桌面透明时保留原生磨砂及侧栏、画布的透明度，但停用全部页面背景滤镜。菜单、下拉框、弹窗和导航抽屉改用不透明主题底色，遮罩仍保留调暗作用。这是视觉降级，不是真实的浮层背景模糊。此模式下设置页隐藏所有模糊、饱和度控件及“菜单与浮层”“弹窗”两行，其余区域只显示有效的不透明度。区域重置只影响可见参数，不清除隐藏值。关闭桌面透明并保存后，完整设置与原有参数恢复。Web 和其他平台不应用此兼容策略。

大弹窗的标题与设置导航保留磨砂层次，表单、模型列表、系统提示词等内容区使用实色底。右侧会话树、统计与遥测共用信息栏材质，标签页不再覆盖实色底。统计摘要共用一块薄填充，宽侧栏两列、窄侧栏单列。详细分组背景透明，仅保留顶部弱分隔线，不重复模糊。文件正文保留稳定底色。侧栏控件使用薄填充。输入器、菜单与弹窗按浮起程度使用不同阴影，仅保留细微的上沿高光和下沿暗部。聊天区与输入器外围由同一层画布承载，不叠加额外背景或渐变。

命令、参数和文件补全在输入器内部、编辑框上方展开，沿用输入器表面，不使用独立浮层。方向键与 Tab 可进入候选，候选内按 Esc 返回编辑器。

页面内 `blur` 和 `saturation` 不能调整原生材质，也不能模糊窗口外的内容。后方没有页面内容时，调整这些参数可能没有明显变化。Web 只使用页面内材质，不透出浏览器后方的桌面。

系统“减少透明度”、增强对比度或强制颜色模式优先于材质参数。关闭磨砂或减少透明度时，表面恢复实色，遮罩仍保留调暗作用。低不透明度无法保证任意桌面背景下的文字对比度，长时间阅读建议保留较厚的表面。

配色沿用 OneChat 的 OKLab 混色与对比度校正机制。深色恢复接近中性的炭灰底色，主画布不额外混入侧栏色。较亮的中性灰只用于统计摘要与控件薄填充，不作为全窗底色。深浅模式使用同一主题色，大面积表面保留原有的轻微染色。强调色按基础底色校正，按钮、链接与焦点沿用同一强调色。浅色用户消息使用 16% 强调色混色，深色保持 22%。浅色输入器与工作区弹层共用柔和灰白底并减弱高光，工作区筛选框也采用同色实底。输入器与弹层仍使用各自的材质参数，其他菜单底色与深色模式保持原样。按钮文字单独适配，辅助文字与消息气泡内链接按承载表面校正对比度。代码高亮保留原有语义色，统计进度条采用半透明中性底槽。

字号以 px 输入，范围为 8–48，允许小数。辅助信息和标题按固定比例派生，内部相对单位继续响应浏览器缩放。界面字号不改变对话正文和代码字号。选择 Enter 发送时，Shift+Enter 换行，Ctrl/⌘+Enter 仍可发送。输入法组字和补全菜单优先处理键盘事件。

字体设置使用有序字体链。点击字体设置可添加、修改、上移、下移或删除字体，第一项优先。输入框同时支持手写名称和本机字体补全，选择候选、按 Enter 或点击添加 / 保存后写入配置，不逐键保存。方向键选择候选，Escape 先关闭补全，再撤销输入草稿。已添加的字体不能重复添加，代码字体不限制为等宽字体。保存失败时保留草稿，字体链不变。

点击“读取本机字体”后才请求访问权限，界面与代码字体共享本次设置中读取的列表，可手动刷新。Desktop 使用本机字体。Web 使用访问网页的设备字体，需要浏览器支持本地字体访问、安全上下文和用户授权。HTTPS、localhost 和 127.0.0.1 可提供安全上下文，普通局域网 HTTP 地址不能使用此 API。不支持或未授权时仍可手写字体，不使用后端字体列表代替。读取到非空列表后，未列出的已选字体显示“本机列表未找到”，但不阻止保存或改写配置。

配置中的每项是一个字体族名称，不是逗号分隔的 CSS 字体串。例如：

```json
{
  "fonts": {
    "ui": ["Inter", "Noto Sans SC", "Apple Color Emoji"],
    "code": ["JetBrains Mono", "Noto Sans Mono CJK SC"]
  }
}
```

浏览器按顺序为字符选择字体。界面字体链末尾固定追加 `system-ui, sans-serif`，代码字体链末尾固定追加 `ui-monospace, monospace`，无需写入配置。空数组或删除对应覆盖项表示系统默认。预览展示整条字体链的中英文、数字、符号、表情和代码效果。

字体字段已改为数组，不再接受旧的单字体字符串。旧配置如 `"ui": "Inter"` 需改为 `"ui": ["Inter"]`。旧默认值 `"system-ui"` 和 `"monospace"` 可改为 `[]`，也可直接删除对应覆盖项。

表单只写覆盖项，保留 JSONC 注释，也可直接编辑完整文件。回转箭头图标重置对应设置，底部图标恢复全部 GUI 默认设置。配置校验失败时显示错误，并允许通过编辑器修复。保存使用原文校验和原子替换，拒绝覆盖编辑期间的外部修改。

### 存储管理

“系统与扩展 → 存储管理”统计运行 opi 的电脑上的全局会话、输入历史、遥测、离线报告、程序资源缓存、工具临时文件和 SDK 日志。Desktop 窗口还提供 Electron HTTP 缓存和 GUI 诊断日志的统计。项目目录、配置、凭据和扩展安装文件不参与清理。

按分类展开条目，可搜索名称或路径、选择本页可删除项、批量删除或单独删除。大小来自文件元数据，表示已识别文件的逻辑大小，不代表整个目录或磁盘的实际占用。无法读取的分类或条目会提示统计不完整。删除立即生效，不经过回收站，不需要点击设置页的“保存”。

清理前须等待所有会话任务结束，并确认其他 Pi / opi 实例已关闭。全局数据可能与原版 Pi 共用。当前已打开的会话、当前程序资源、正在记录的遥测、MCP 当前日志和 GUI 当前诊断日志受保护。临时文件还保留最近 24 小时的内容，删除旧工具输出后，对话中的文件链接可能失效。已打开的会话切换后需等待执行资源释放，才能在此删除。

扫描不跟随条目内的符号链接。删除只接受最近一次扫描生成的条目标识，并复核目录、文件身份和修改时间，变化时要求刷新。输入历史清理与写入共用文件锁，诊断日志清理与轮转共用队列。批量删除不是事务，中途失败时刷新列表检查剩余内容。

应用自有写入位置与扫描共用 `src/harness/storage/paths.ts`，会话目录使用 SDK 的实际路径，Desktop 使用 Electron 目录及缓存 API。修改写入位置时无需另改界面路径。SDK 没有提供枚举接口的临时文件名集中在存储来源模块中适配。Desktop 只清理 HTTP 缓存，不删除整个 Chromium 数据目录，不重置布局或登录状态。Web 页不管理访问者浏览器的本机缓存。

### 模块全局配置

设置页提供模块默认配置对应的用户层编辑入口。工具选择器可将当前选择保存到全局 `settings.json` 的原生 `defaultTools` 数组。除已有的会话行为页外，模块配置不需要活动会话。路径沿用各模块的配置加载器，包括模块专属环境变量重定向，界面显示后端实际路径。

常用开关、数字、枚举和列表使用 shadcn/ui 表单。审批规则、LSP 服务器定义、子代理覆盖、提示词、模板和其他参数在同页切换到 JSONC 编辑。默认配置可展开只读查看。

“网络与网页”中的“搜索引擎”将启停开关和上移、下移按钮放在同一行，按配置顺序显示。引擎标识与名称来自 schema 的数组选项 `const` / `title`，前端不维护名称映射或固定数量。排序复用模型列表的位移动画，并尊重系统的减少动态效果设置。顺序和各开关可分别恢复默认，修改统一保存到 `websearch.provider_order` 和各引擎的 `enabled`。

表单区分“继承默认”和“全局覆盖”。重置删除覆盖字段，不写入当前默认值。显式设置为默认值仍保留覆盖。列表每行一项，整体替换默认列表。禁止访问路径列表尤其需要保留仍要保护的条目。

模块配置采用显式保存，保留 JSONC 注释。切换分类保留草稿，关闭设置时确认是否放弃修改。保存前校验 JSONC 和模块 schema，使用原文版本检查及原子替换，拒绝覆盖外部修改。发生冲突后可先复制草稿，再放弃修改并重新读取。

保存仅写全局文件，不重载或中断当前任务。模块下次读取配置时应用修改，已加载的组件需要在任务结束后重载或重启。支持项目层的模块会显示项目配置候选路径，此页不计算项目最终生效值。Cookie、权限审批和 Discord 详细档案旁提供安全或隐私提示。搜索 API 密钥建议使用环境变量引用，JSONC 编辑器不会遮蔽文件中的明文值。

### MCP

“设置 → 连接与集成 → MCP 服务”编辑用户级 `~/.pi/agent/mcp.json`。默认展示服务列表，服务与表单条目的增删使用列表过渡，表单使用折叠组件的展开收起动画，下拉选项使用统一 Select 组件。服务行直接提供启停开关、复制和删除图标。删除复用会话列表的两步确认，Ctrl/Command+点击可直接删除，修改仍需统一保存。开关表示配置中的 `enabled`，不表示实际连接状态。此页不提供连接测试、登录或重连管理。

本地进程表单提供启动程序、逐项参数、环境变量和工作目录。“粘贴启动命令”按 POSIX 引号与转义拆分到表单，不执行命令，不支持 shell 变量展开、管道、重定向或多行命令。Windows 路径建议直接填写参数列表。本地进程和环境变量均属于运行 opi 的机器，不是浏览器所在设备。

远程 HTTP 表单提供服务地址、自动 OAuth、Bearer Token、自定义请求头和已登录提供商凭据。OAuth 客户端、回调与授权服务器选项默认折叠。工具与高级设置提供能力描述、请求超时、`exposure` 和可排序的 `toolExposure` 规则。精确工具名优先于通配规则，通配规则按排列顺序匹配。隐藏工具不会停止服务连接。`autoEnableCodemode` 保留在高级 JSON 中，opi 不允许 MCP 自动把普通会话切换为脚本模式。

“导入配置”接受完整 `mcpServers` 或单个服务对象，预览后导入草稿，不导入顶层全局选项。同名服务必须确认替换或改名，`-` 与 `_` 造成的名称冲突需要改名。导入不连接服务，也不执行凭据命令。

所有修改沿用设置页的统一保存与放弃。切换分类保留草稿，保存前校验名称、连接字段、认证和 OAuth 约束，并拒绝覆盖外部修改。表单保留未修改的配置字段和未知字段，JSON 入口用于高级编辑或修复损坏配置。保存不会中断现有会话，新会话或 `/reload` 后生效。

会话工具选择器中的“MCP 服务工具”提供服务总开关和单工具开关。关闭总开关会隐藏该服务的专属工具，包括之后新增的工具，不改变单工具选择，重新开启后恢复原选择。标题旁的三态复选框同时控制服务总开关和共享资源工具开关，筛选时只作用于匹配项。全部开启时显示勾选，全部关闭时显示空框，部分开启时显示横线。点击空框或横线开启全部，点击勾选关闭全部。点击范围与工具项一致，仅勾选框和标题文字可切换。勾选框统一放在左侧，同级对齐，子工具统一缩进，服务折叠箭头位于最右侧。自动管理的工具显示禁用态勾选框。

关闭的工具设为 `hidden`，不再声明、发现或调用。选择按当前会话分支保存，工具刷新、恢复和重载不会清除选择，不修改 MCP 配置，也不影响其他会话或连接。重新勾选只恢复配置的暴露方式，延迟工具仍需搜索加载。普通模式下，存在可用但尚未加载的延迟工具时启用 `tool_search`，全部关闭或加载后自动停用。codemode 的 `searchTools()` 保持 SDK 行为。

“共享资源”提供 `list_mcp_resources`、`list_mcp_resource_templates`、`read_mcp_resource` 的手动开关，不受单个服务总开关影响。开启时仍可访问已关闭专属工具的服务资源，也支持只提供资源的服务。清空筛选后，通过标题旁的总复选框可同时关闭所有服务工具和共享资源工具。

受信任项目的 `.pi/mcp.json` 沿用 Pi 原生加载规则，项目同名服务覆盖全局服务。全局编辑页不修改项目配置或扩展注册的服务。`/mcp` 打开设置中的 MCP 页，`/mcp login`、`logout`、`reconnect` 及服务器名补全继续使用原生实现。

仅配置可信 MCP 服务。表单默认遮蔽环境变量、请求头和客户端密钥，可主动查看。遮蔽不加密配置文件，JSON 编辑器仍会显示明文值。凭据建议使用 `${ENV_NAME}` 引用，保存时保留引用而不展开。`!command` 会标记为命令取值，编辑与校验阶段不执行。使用提供商凭据会将该提供商的登录令牌发送到配置的服务地址。

Pi 1.1.0 的授权请求有上游超时，会话关闭会取消登录并释放回调监听器。GUI 关闭时先启动 SDK shutdown，再等待命令结束，避免授权请求阻塞关闭。SDK 尚未公开非 TUI 登录的独立取消信号，因此“取消登录”可取消备用输入框，但不能中断授权请求准备阶段。此阶段需等待上游超时或关闭会话。

GUI 通过公开的 `createMcpExtension` 和 `registerTool` 接口调整工具暴露，连接、执行和 OAuth 沿用 SDK。依赖使用 `latest`，不使用依赖补丁或 SDK 内部导入。

## 消息发送模式

输入框中工具按钮旁的图标与文字按钮可点击切换 Steering（引导）和 Follow-up（跟进），默认 Steering。选择仅在当前界面临时生效，不写入全局配置，刷新或重启后恢复默认。窄屏只显示图标。

任务运行中，Steering 在下一次可介入时引导任务，Follow-up 等当前任务结束后处理。切换不改变已排队消息。运行中有输入时，发送按钮显示对应模式图标，无输入时显示停止图标。空闲时显示向上箭头，正常发起对话。

## 可拖拽布局

宽屏下拖动左右分隔线调整侧栏宽度。消息正文两侧的感应区可连续调整正文与输入器宽度，边缘高光只在鼠标靠近时显示，并跟随鼠标纵向位置。左栏会话与文件区之间的横向分隔线调整文件浏览区域的高度。

所有拖拽边框均支持双击恢复该项默认值，不重置其他尺寸。键盘方向键微调，Home 或 Enter 恢复默认，Esc 取消当前拖动。默认左栏宽度为 20%，右栏为聊天工作区的 34%，对话最大宽度为 100ch，左栏会话区域占可分配高度的 55%。实际尺寸受窗口空间和最小可操作尺寸约束。

尺寸保存为客户端本地布局状态，不进入 `gui.jsonc`。只有完成拖动或重置时保存，窗口变小和切换手机布局不会覆盖记住的宽屏尺寸。Desktop 与各浏览器分别保存，窄屏继续使用抽屉、上下分屏和会话/文件切换。

## Desktop 的 Web 访问

默认关闭。在“设置 → 桌面 Web 访问”中调整启用开关、监听地址和端口，或编辑用户 `gui.jsonc`：

```jsonc
{
  "desktopWeb": {
    "enabled": true,
    "host": "127.0.0.1",
    "port": 19199
  }
}
```

开关自动保存，地址和端口在失焦或按 Enter 时保存。支持单项重置，恢复 GUI 默认设置也会关闭此功能。修改仅在下次启动 Desktop 时生效，保存不会中断当前连接或任务。`opi-web` 仍使用自己的启动参数和独立后端，不使用这些监听配置。

Desktop 的 Web 服务与桌面界面共用一个 `GuiHost`。浏览器打开同一会话后，可查看实时输出、继续发送、停止任务和处理审批。各客户端独立选择会话，草稿和阅读位置不互相覆盖。无需另外启动 `opi-web`，也不依赖 `pi-server` 或 `pi-client`。

监听成功后，标准输出显示 `opi-desktop web: http://127.0.0.1:19199/`，端口为 `0` 时以此输出为准。配置无效、地址不可用或端口被占用时，不启用 Web 服务，并在桌面弹窗和 stderr 中报告错误，桌面端可继续使用。不会自动改用其他端口。

Desktop 提供 HTTP 访问，无登录认证。默认回环地址适合 SSH 隧道。在随身电脑运行：

```sh
ssh -N -L 19199:127.0.0.1:19199 user@linux-host
```

随后在随身电脑浏览器打开 `http://127.0.0.1:19199/`。SSH 提供认证和加密，无需向公网开放 Web 端口。监听 `0.0.0.0` 会允许其他设备连接，仅可用于可信网络。同源校验不代替身份认证，勿直接暴露到公网。

浏览器刷新或 SSH 断开不停止任务。关闭桌面窗口会按现有行为退出 Desktop，关闭 Web 服务并结束任务，不会转入后台常驻。后端电脑也需保持开机且不休眠。

## Web 访问与手机

参数及默认值见 `opi-web --help`，访问地址以启动输出为准，无需登录或访问密钥。监听 `0.0.0.0` 时，本机访问需将输出地址中的主机替换为 `127.0.0.1`，其他设备访问需替换为电脑的局域网 IP，保留协议和端口，并确保防火墙允许该端口。仅本机使用时可指定 `--host 127.0.0.1`。

所有能连接该端口的设备都能控制后端电脑上的文件和进程。仅用于可信局域网，请勿暴露到公网。同源校验不代替身份认证。

浏览器刷新、断网或手机锁屏不结束后台任务。重连后读取 SDK 当前状态和尚未处理的审批，不自动重发操作。

TLS 可选：

```sh
./dist/web/opi-web --cwd /path/to/project --host 0.0.0.0 \
  --cert /path/to/cert.pem --key /path/to/key.pem
```

使用 TLS 时，通过 HTTPS 访问，端口以启动输出为准。证书需要被设备信任，并匹配访问地址中的 IP 或域名。当前没有可信反向代理配置，不接受代理转发的协议头。

宿主支持单用户、多会话并行。各页面独立选择会话，同一会话在宿主内只使用一个运行实例。切换、刷新和断线不停止后台任务，审批响应只消费一次。操作携带提交时的目标会话，停止当前会话不会取消其他会话。此功能不提供多用户权限隔离。

实例按需加载，无人查看的空闲实例按最近使用顺序和空闲时长回收。执行、排队、等待交互和后台命名期间保活。回收不删除会话，重新打开会恢复历史和本次宿主运行期间的会话授权，项目的“仅本次信任”也在当前宿主内复用。关闭宿主会取消任务并等待必要写入，不支持进程崩溃后自动续跑。

回收策略通过设置页的“编辑 gui.jsonc”配置，不提供单独表单：

```jsonc
{
  "sessionCache": {
    "idleLimit": 3,
    "idleMs": 60000
  }
}
```

未超时的实例全部保留，不占用 `idleLimit` 额度。每次扫描只将已超时且可安全释放的实例纳入淘汰候选，按 `lastUsed` 保留最近使用的 `idleLimit` 个，其余释放。候选数量未超过额度时，即使持续闲置也会保留。运行中、排队和等待交互等实例仍受原有保护，不进入候选池。

`idleMs` 同时控制超时判断和扫描间隔，超时只是进入候选池的门槛，不代表到时必然释放。`idleLimit: 0` 也必须先超时，再在扫描时释放。总实例数可以超过 `idleLimit`：不可回收的实例、未超时的实例，以及额度内保留的超时实例都会驻留。

Web 和 Desktop 均在宿主启动时读取策略。在 GUI 保存后立即更新策略，已有回收计时器按新间隔重新计时，不重载或中断会话。直接修改文件需要重启宿主，或在 GUI 中重新保存。启动时配置无效则使用默认策略，仍可进入设置修复。

逻辑会话 `GuiSession` 长期登记，SDK、执行期任务和载荷由可回收的 `GuiExecution` 持有。回收、删除和退出共用资源收尾，但分别检查准入条件。登记不代表已经加载，未落盘会话也可通过统一打开入口恢复。初始状态重放不建立临时订阅，也不触发额外读取。

导航身份独立于聊天快照。同工作区切换、执行资源加载和重连不会清空文件预览、目录展开或侧栏搜索。全局配置查询不随会话切换重建，文件与 Git 查询属于工作区，不加载 SDK 实例。

页面隐藏后只接收会话概览，返回前台再订阅当前会话详情。草稿、附件、聊天阅读位置和主要展开状态在页面内按会话保存，不依赖运行实例。草稿和附件不保证刷新后保留。多个会话仍可能操作同一项目文件，Git 差异属于工作区，不属于单个会话。

## 界面

界面使用 shadcn/ui 和 Lucide，主布局使用 CSS Grid/Flex。桌面左栏可折叠为图标栏，窄屏左栏使用抽屉，切回桌面宽度时自动关闭。右侧会话信息栏与聊天区分屏，窄屏改为上下排列，各区域独立滚动。分屏和居中悬浮窗使用弹性布局与相对尺寸，不通过绝对定位排列。

配色、磨砂层次、字体与间距、组件状态及响应式布局约束统一记录在 [GUI 设计语言](../DESIGN.md)。

聊天顶栏的“会话操作”菜单提供系统提示词、命令帮助、导入和导出。设置、认证、模型、套餐用量与重载资源按此顺序位于左栏底部。输入框底部的工具按钮显示启用数量，点击打开工具配置。模型、工具、设置、认证、系统提示词和命令帮助均使用悬浮窗。欢迎页的快捷入口只填入草稿，不自动发送。

会话信息栏默认展开，包含会话树、会话统计和遥测。三个页面随会话变更自动更新，流式变更合并读取，不提供手动刷新。顶栏按钮可收起或展开，收起后保留所选标签。切换会话时默认展开，打开悬浮窗不会关闭会话信息栏。

点击会话树的消息正文可定位聊天位置，自动展开所在处理过程。旧分支和已压缩消息在聊天区只读预览，不改变活动分支，点击“返回当前会话”退出预览。树中的切换、总结后切换、创建分支和标签按钮仍执行对应 SDK 操作。

聊天正文使用自然布局，完整挂载当前展示的消息。过程与通知的展开状态随会话视图保存，切换回来恢复阅读位置，不重放上一次消息定位。输入草稿不重新渲染未变化的聊天。会话树超过 100 行后只挂载视口附近的行，获得焦点的行和文本选区保留挂载。

历史会话和工作区目录在连接时全量发送，后续复用未变化区间，只发送修改记录和顺序变化。重连重新建立全量基线，背压合并以最后实际发送的状态为准。

界面按钮发送类型化的 GUI 操作，后端直接调用 SDK 接口或已注册的处理函数，不模拟斜杠输入，不写入输入历史。手动输入斜杠命令仍走原有流程。

左栏顶部显示工作区选择器，同时决定会话和文件的范围。下方分为会话管理和项目文件两个独立滚动区，分隔线可拖动，也可用方向键调整，比例在当前客户端持久化，双击恢复默认。文件区可收起为底部工具栏上方的一行，不关闭右侧预览。窄屏和可用高度不足时通过“会话 / 文件”切换浏览区域。工作区下拉框支持路径筛选，先列出启动目录，再列出历史中的不同工作区。桌面端“选择目录”打开系统目录选择器，Web 端打开服务端目录浏览弹窗，支持输入路径、返回上级和筛选子目录，不上传浏览器本机目录。

当前工作区的会话条目在运行时显示强调色渐变光带，前端颜色最深，尾部逐渐变淡。光带沿边框周长匀速移动，每圈 6 秒，不表示完成百分比。结束且未读时光带闭合成完整边框，已读后恢复普通样式。等待交互时使用静态边框和审批图标。其他工作区有运行任务、待确认或未读结果时，工作区选择按钮显示静态强调色边框。下拉选项不显示边框动画，在原勾选位置显示状态：待审批为实心小盾，运行中为呼吸圆点，未读为实心圆点。其他工作区有待审批会话时，选择按钮在展开图标左侧也显示实心小盾。折叠侧栏时，小盾替换工作区文件夹图标。待审批优先于运行状态，处理完审批后恢复运行或未读提示。当前工作区无待处理状态时恢复勾选，未读状态独立保留。开启系统减少动态效果时不播放循环动画。

已读状态按浏览器标签页保存。只有对应会话在前台、窗口有焦点且聊天处于最新位置时才确认已读。打开工作区下拉框不会清空未读。会话行以标题字重标记未读，以实心小盾标记等待交互。后台审批不弹窗，进入对应会话后使用原有审批弹窗，不新增审批控制面板。

Web 与 Desktop 的 Bash 审批共用结构化展示。工作目录和原因弱化显示，命令使用现有 Prism 高亮，策略要求确认的命令和写入目标单独强调。长命令默认预览前 240 个 Unicode 字符、最多 4 行，通过现有 shadcn `Collapsible` 和 `Button` 展开完整内容，沿用项目的折叠动画与减少动态效果设置。预览裁剪不修改命令，敏感操作列表不随主命令折叠。待确认单元与完整命令完全相同时，只展示一次代码，下方保留确认提示和原因。仅预览相同的不同命令不合并。展开不会提交审批，批准后仍执行原始完整命令。Bash 审批不额外显示底部的“取消 / 拒绝”按钮，通过 `Deny` 或 `Esc` 拒绝。

下拉列表中的工作区可点击行末移除按钮，再点对钩确认。移除会永久删除该工作区的全部会话文件并移除列表入口，保留项目目录和文件，不写入移除标记或删除日志。失效目录标记“目录不存在”，不能切换但仍可移除。启动目录、当前工作区以及包含运行中、待确认或未读会话的工作区不提供移除入口。

侧栏仅展示当前工作区的会话，按修改时间从新到旧连续排列，不按日期分组，也不限制为六条。搜索框筛选当前工作区的全部会话标题，不搜索消息正文。新建会话位于搜索框旁。`/resume` 打开全部工作区的分组列表。

文件树按目录逐层加载，目录优先、名称排序，支持方向键导航。Git 忽略项仍可浏览和引用，以较暗的颜色显示，仅隐藏 `.git` 内部元数据。分支、变更数量和行末状态均来自工作区 Git 状态，不代表当前会话独自产生的修改。文件区标题行依次提供折叠入口、分支名、变更数量按钮、刷新和折叠全部目录。点击变更数量切换为按相对路径平铺的变更列表，包含已删除项，忽略项不计入变更。非 Git 目录正常浏览。文件与 Git 信息在工作区切换、任务结束、窗口返回前台或手动刷新时更新，不持续监听磁盘。

点击文件在右侧打开单个“文件”标签，后续点击替换预览。切换到会话信息再返回时保留预览及阅读位置，关闭文件返回之前的会话信息标签。预览只读，不另开弹窗。“引用文件”将 `@路径` 插入草稿，不自动发送。浏览、缩放和翻页不向模型上下文添加内容。文件浏览与预览限制在当前工作区内，拒绝通过符号链接访问外部文件，不提供文件编辑或 Git 写操作。

- 文本：支持 512 KiB 以内的 UTF-8 文本及统一差异。已暂存与未暂存差异分开显示，有差异时默认展示差异，可切换到内容。默认自动折行，关闭后正文使用同一个横纵滚动视口。非 UTF-8 文本、超限文本和不支持的二进制文件显示说明。
- 图片：支持 PNG、JPEG、GIF、WebP、SVG，默认保持比例适应窗口，小图不放大。`1:1` 按钮恢复实际大小 100%，四角图标恢复适应窗口。支持拖动和透明棋盘格背景，显示像素尺寸、文件大小和缩放比例。鼠标滚轮直接以指针位置为中心缩放，无需组合键，也支持双指手势。缩放按钮、`+`、`-` 键及每次纵向滚轮事件均向对应方向移动到下一个 5% 档位，不按滚动量改变步长。聚焦图片后可用方向键移动。动态图由浏览器播放，SVG 仅作为隔离图片加载，不插入页面 DOM。
- PDF：默认适应宽度、连续滚动，支持翻页、输入页码后按 Enter 跳转、缩放和适应整页。在正文内按住 Ctrl/⌘ 滚动鼠标滚轮，按 5% 档位缩放 PDF，不触发浏览器页面缩放。普通滚轮保持滚动阅读。聚焦正文后可用 PageUp/PageDown 翻页。文字层支持选择、复制，扫描件不做 OCR。只挂载可视页及邻近页，最多同时渲染两页，每页画布不超过 800 万像素或单边 8192 像素。加密 PDF 提示先解密，损坏或读取失败时显示错误。图片和 PDF 不生成 Git 内容差异，也不显示文本折行按钮。

图片和 PDF 的缩放按钮按 5% 分档，非档位比例放大到相邻较高档、缩小到相邻较低档，例如 132.99% 放大到 135%、缩小到 130%。适应模式、图片双指手势和手动输入不限制在档位上。缩放百分比可直接编辑，支持小数及末尾 `%`，按 Enter 或移开焦点应用，按 Esc 取消。仅聚焦而未编辑不改变适应模式或缩放精度。图片手动输入范围为 1%–3200%，PDF 为 10%–800%，超出范围调整到边界值，空值、非正数和无效输入恢复原比例。

图片和 PDF 不设置文件字节数上限，不通过 JSON 或 IPC 传输完整 Base64。预览查询只读取文件头和元信息，随后通过绑定客户端、工作区和文件版本的资源地址流式读取。Web 和 Desktop 共用 Range 与版本校验，PDF.js 按需请求分段，不预取整份文档。刷新未变化的文件时复用资源地址，保留阅读状态。PDF 更新后保留缩放和页码，并将页码限制在新文档范围内。切换或关闭文件时释放阅读器资源。

不设文件大小门槛不等于任意文件都能打开。图片仍由浏览器解码原图，尚未实现超大像素图片的缩略图生成或分块解码，内存开销取决于像素量和浏览器实现。PDF 的文件结构、嵌入资源和浏览范围也可能导致大量读取。遇到解码或读取错误时可重试，文件已变化时需刷新文件区。PDF.js、Worker、字体、CMap 和 WASM 均随应用打包，不依赖 CDN。

点击历史会话同时恢复对应工作区和消息。跨工作区恢复保留项目信任确认，运行任务期间仍可切换或新建会话。工作区选择优先返回该页面上次查看的会话。工作目录或会话文件已删除时显示错误，不创建替代会话。

会话和工作区列表的行末按钮通过 Grid 同格叠放在列表项上层，不单独占列或挤压文字。按钮在悬停或键盘聚焦时显示，触屏始终显示，操作区使用不透明背景遮挡下方文字。会话行提供重命名、删除按钮。名称原位编辑，Enter 或失焦保存，Esc 取消，空名称不保存，与聊天顶栏一致。重命名非当前会话不会切换会话。删除按钮第一次点击变成对钩，第二次点击才删除，不打开弹窗。失焦或 Esc 取消待确认状态。会话删除支持 Ctrl+点击跳过确认，macOS 可用 Command+点击，但仍执行目录边界、文件身份和运行状态检查。工作区移除始终需要二次确认，不提供二级菜单，移除会删除该工作区的会话记录。删除不进入回收站，无法撤销，TUI 中的对应历史也会消失。只删除共享历史中的普通会话文件，不删除项目目录、代码、配置，也不清理独立的输入历史、导出文件或遥测记录。

删除当前会话后，查看它的页面在同一工作区进入新会话。运行中、等待交互或未读会话不显示删除按钮，读取最新结果后才恢复删除入口。不限制删除其他空闲且已读的会话。其他页面正在使用的工作区不能移除。客户端根据后端实际删除结果清理草稿、附件、阅读和折叠记忆。扩展否决时不清理，批量部分失败时只清理已删除项，迟到上传和发送失败回调不能重新创建已删除记录。删除准备期间发现会话文件被其他进程修改时会停止删除。删除前应关闭其他 TUI 中正在使用这些会话的窗口，GUI 无法阻止外部进程继续写入。

历史索引独立于流式快照传输。启动、重连、会话切换、重命名及回复结束时更新。窗口回到前台或页面恢复可见时重新读取，也可点击刷新图标获取 TUI 在外部新增、改名或删除的会话。不持续监听目录，也不随每个流式片段扫描磁盘。

侧栏“模型”和 `/model`、`/scoped-models` 打开同一个悬浮窗。可搜索模型、勾选或移出已选模型、调整顺序，也可直接切换当前模型。勾选和排序仅影响当前会话，点击“保存模型”后写入与 TUI 共用的 `enabledModels` 配置，重启后恢复。直接切换不修改默认模型或已选列表。

输入框的模型与思考级别使用基于 Radix 的 shadcn Select，与其他浮层共享磨砂表面。悬停和展开时显示中性高亮底色、边框和较深文字，选项以勾选标识当前值。支持方向键、字符定位和 Esc 关闭，关闭后焦点返回选择器。模型菜单底部的“管理模型”先收起菜单，再打开与左侧栏“模型”按钮相同的悬浮窗，不切换当前模型。没有可选模型时仍可通过该入口添加模型。

输入框只显示当前可用的已选模型，并保持配置顺序。没有已选模型时禁用下拉列表，提示在侧栏选择。当前模型未加入已选列表时只展示名称，不将它追加到候选项，也不退回全部模型。

菜单和会话信息标签页支持键盘导航。悬浮窗限制焦点范围，会话信息栏不阻止聊天操作。`Esc` 关闭最上层的提示、菜单或悬浮窗。悬浮窗关闭后焦点返回输入器，嵌套悬浮窗则返回上一层。审批弹窗点击背景不会关闭，`Esc` 表示取消或拒绝。

每条实际进入对话的用户消息开启一个处理阶段，模型输出分为“处理过程”和正文。处理过程包含多轮思考、工具调用和中途正文。当前阶段执行或重试时默认展开，确认最终回复、下一条用户消息进入对话，或执行结束、停止、失败时自动收起一次。消息仍在队列中、单次工具完成或等待重试都不会触发收起。历史中的非活跃阶段默认收起，纯文字回复不显示空的过程入口。

执行期间手动收起，不因后续输出重新展开。退出实时追踪时仍会自动收起一次，之后手动展开不会被后续阶段再次收起。正常结束的模型消息由后续用户消息接续且没有最终正文时，显示“已接续”，不冒充完成。模型返回空消息、输出截断、工具结果缺失或工具中止不视为正常接续。失败、停止和未完成状态及错误保留在折叠区外。

有阶段标记时按标记识别最终正文。没有标记时，先实时展示最后一条模型消息尾部的正文，后续出现工具或新模型消息时将旧正文归回过程，等该条回复正常结束再确认最终正文。停止或失败时保留已生成的部分，不标为完成。

思考默认折叠。每次工具调用的参数、执行中输出和最终结果合并在同一个可展开操作行中，成功和失败都默认收起，失败时仍展示错误摘要，手动展开的详情保持展开。子级展开状态不随流式更新或整体折叠重置。上翻阅读或手动展开详情时不强制滚动到底部，可点击“回到最新”继续跟随。

文件读取展示行号和语法高亮，搜索按文件展示片段，编辑和写入展示 diff，Bash 展示命令与纯文本日志。参数按字段和列表呈现，JSON 收在“原始数据”中。外部扩展工具使用通用参数与输出布局。代码块使用 `react-syntax-highlighter` 的 Prism 轻量构建，支持复制和常用语言高亮，未注册语言按纯文本显示。

网页搜索展示标题、域名和摘要卡片，网页读取提供可展开预览、返回范围及续读偏移。仅取得部分静态内容时明确提示。卡片不额外抓取网页或加载远程缩略图，链接通过浏览器新页或桌面默认浏览器打开。源码预览按代码显示，网页 HTML 不执行。

子代理执行时默认展开任务列表，显示并行或串行模式、已结束任务数、各任务状态及最新活动。任务详情包含输出、执行记录、耗时和结果文件路径。同名代理按任务顺序分别展示，失败、停止和未执行不会标为成功。任务的手动展开状态在流式更新和整体折叠后保留。`/run` 面板使用相同的进度视图，可停止整批命令任务。

基础控件位于 `src/gui/ui/components/ui/`，选型配置位于 `components.json`。以下路径均相对于 `src/gui/ui/`：`theme/palette.ts` 生成语义颜色，`theme/theme.css` 将颜色映射到组件并管理材质、字号、间距和圆角的共享变量，`app/style.css` 管理全局布局与共享样式。业务样式随功能归档，例如 `transcript/transcript.css`、`tools/tools.css`、`tools/rich-tools.css` 和 `content/code.css`。

## 前端目录

`src/gui/ui/` 按功能组织，组件、专用 Hook 和样式放在同一功能目录。根目录只保留启动入口 `main.tsx`、`index.html` 和类型声明 `vite-env.d.ts`。

| 目录 | 职责 |
| --- | --- |
| `app/` | 应用组装、布局、侧栏和弹窗，`welcome/` 管理欢迎页、启动动画和更新日志 |
| `runtime/` | 宿主连接、事件状态、查询上下文和认证交互 |
| `composer/` | 消息输入、输入历史、建议和文件拖放 |
| `sessions/` | 会话列表、历史、树、草稿、活动状态和信息栏 |
| `transcript/` | 消息流组织、回复阶段、定位和滚动 |
| `tools/` | 工具选择、审批、执行状态和结果展示 |
| `content/` | Markdown、代码、公式和技能卡片 |
| `workspace/` | 工作区选择、目录树和工作台，`preview/` 管理文件、图片、PDF 和差异预览 |
| `settings/` | 配置编辑、外观、模块和 MCP 设置 |
| `models/` | 模型选择、管理和配置 |
| `components/` | 跨功能复用的交互组件，`ui/` 保存基础控件 |
| `lib/` | 跨功能通用逻辑 |
| `theme/` | 主题生成、应用和全局主题样式 |
| `reports/` | 统计、用量和遥测报表 |
| `public/` | 静态资源 |

新增文件归入对应功能目录，不按文件类型另建全局 `hooks/` 或 `styles/`。全局样式在 `main.tsx` 按顺序加载，功能组件直接引用自身样式。

| 工具启停、分支恢复、保存用户默认 | 输入框底部工具按钮、`/tools` |
| 系统提示词、会话统计、用量、遥测 | 顶栏菜单、右侧标签页、左栏用量按钮，保留 `/system`、`/stats`、`/usage`、`/telemetry` |
| 技能、提示词模板、其他业务扩展命令 | SDK `prompt()` 分发，命令与参数补全 |
| 子代理 | `subagent` 工具、`/agents`、`/run`，图形进度与取消 |
| 上下文裁剪、LSP、Presence、o-pet | 原有 harness 业务与命令 |
| 用户 Shell | `!`、`!!`，执行语义与 SDK/TUI 一致 |
| 文件树、Git 状态、只读预览和差异 | 左栏文件区、右侧“文件”标签 |
| 文件引用、上传、粘贴图片 | 文件预览的引用按钮、`@路径`、附件按钮、剪贴板 |
| 输入历史 | 输入区历史图标菜单，与 TUI 共用持久记录 |

默认使用按钮或 `Ctrl/⌘ + Enter` 发送，`Enter` 换行。GUI 设置可改为 `Enter` 发送、`Shift + Enter` 换行。输入 `@路径前缀` 后按 `Tab` 获取后端目录候选。上传单文件暂限 3 MB，最多 8 张图片。后端 `@` 附件暂限 8 MiB，二进制附件提供路径供文件工具读取。

`!`/`!!` 是用户直接执行 Shell，不走模型工具的 Approval Gate，与现有 TUI 行为一致。

## 实现边界

- `src/gui/host/` 创建和绑定 SDK runtime，处理图形交互、生命周期及输入校验。会话、队列、压缩、重试和工具执行仍由 SDK 管理。
- `src/gui/contract.ts` 只定义跨边界操作参数与可序列化的界面数据，不提供新的 Agent 或 Session 门面。
- `src/gui/ui/` 不导入 Node、Bun 或 SDK 的运行时代码。消息中的 HTML 不执行，远程图片不自动加载。
- GUI 产物启动的子代理通过 `PI_SUBAGENT_CHILD` 进入 `src/harness/runtime/headless.ts`，复用上游 CLI JSON 执行能力并只装配业务扩展，不导入 TUI 入口。Desktop 子代理使用 Electron 的 Node 模式，仍沿用子进程环境变量白名单。
- `src/desktop/` 提供隔离的 Electron 宿主、限定的 preload 桥接、目录选择和文件保存。可在 SDK utility process 中为同一个宿主开启 Web 监听，复用 `src/web/server.ts` 和共享 GUI 静态资源。渲染进程没有 Node 权限。
- `src/web/` 提供静态资源、来源校验和状态订阅。免登录，仅用于可信局域网，TLS 可选。
- `harness` 的呈现器由宿主注入。TUI 呈现器仍只在 TUI 模式使用，GUI 不加载它们。

当前 SDK 没有 `gui` 模式标识。GUI 绑定 `mode: "print"` 和真实 `uiContext`，SDK 据此提供 `hasUI: true`。这不调用 `runPrintMode()`，也不使用 RPC。扩展应通过 `hasUI` 判断标准对话能力，通过 `mode === "tui"` 判断终端组件能力。

支持外部 TS/JS 扩展的工具、命令和标准对话接口。不支持把 `ctx.ui.custom()`、终端编辑器、终端输入监听或终端组件工厂转换为网页。TUI 动效、主题、布局和快捷键不逐项复刻。统计、遥测和复杂工具详情使用图形组件，不保证与 TUI 相同的视觉呈现。

MVP 不承诺任意外部扩展都能在 GUI 使用，尤其是直接依赖终端模式判断、同步编辑器状态或终端组件的扩展。也不承诺任务在应用退出、服务进程重启后继续执行。

## 验证

日常改动按 `AGENTS.md` 的测试约定选择验证范围，例如配置改动：

```sh
bun run typecheck
./node_modules/.bin/vitest run tests/gui/config.test.ts tests/gui/settings-draft.test.ts
```

确需验证浏览器交互或打包资源时，按文件选择无头 Web E2E：

```sh
bun run test:gui tests/gui/preferences.e2e.ts --project=desktop
```

这里的 `desktop` 是浏览器大屏视口，`phone` 是窄屏视口，均不启动 Electron。省略文件会运行整套 Web E2E，不作为日常验证步骤。

工作台测试覆盖真实 Git 仓库的忽略项、暂存与未暂存差异、重命名、删除、未跟踪文件、子目录及路径边界，以及会话搜索、文件区折叠、键盘导航、右侧预览和 200% 字体布局。深浅色截图位于 `dist/gui-workbench-{light,dark}-*.png`。

Web E2E 使用已安装的 Playwright Chromium，无头运行，不需要桌面显示环境。原生桌面用例位于 `desktop-*.e2e.ts`，仅由 `test:desktop` 入口运行，不重复验证通用页面交互。该入口会启动可见 Electron 窗口，Playwright 的 `headless` 选项不会隐藏这些窗口。获得用户同意后，Linux 可在已安装的虚拟显示环境中运行定向用例：

```sh
xvfb-run -a bun run test:desktop tests/gui/desktop-protocol.e2e.ts
```

缺少运行环境时先报告，不自动下载安装。测试使用隔离 HOME 和本地模型 HTTP 服务，不读取个人认证，不调用付费模型。PDF 图片传递在 `pdf.test.ts` 通过宿主集成测试验证。协调进程的共享与退出由 `coordinator.test.ts` 覆盖，桌面子进程的 Node 启动参数由 `invocation.test.ts` 覆盖。`desktop-runtime.integration.ts` 只检查打包后端在 Node 模式启动和退出，不创建窗口，可通过 `bun run test:desktop tests/gui/desktop-runtime.integration.ts` 单独运行。
