# 技能

`skill` 工具按名称加载技能，`/skill:<name>` 手动加载，`/skill` 查看当前分支的加载记录。加载后的资源通过 `skill://` 访问。

## 发现

用户技能来自 `~/.pi/agent/skills` 和 `~/.agents/skills`。受信任项目还会从当前目录向上发现 `.agents/skills` 和 `.pi/skills`，直到最近 Git 根目录，非 Git 目录则查到文件系统根。

Pi 负责当前目录的 `.pi/skills`，opi 补充祖先目录。技能扫描沿用 Pi 的递归、忽略和 `SKILL.md` 解析规则。

同名技能中，项目级优先于用户级，同一范围保留最先发现的条目。

## SKILL.md

```markdown
---
name: review
description: 审查代码改动。当用户要求代码审查时使用。
disable-model-invocation: false
---
检查改动中的逻辑错误和边界条件，按影响程度报告问题。
```

| 字段 | 行为 |
| --- | --- |
| `name` | 可省略并使用父目录名，建议显式填写。1–64 个小写字母、数字和连字符 |
| `description` | 必填，非空，最多 1024 字符，用于索引 |
| `disable-model-invocation` | 严格布尔 true 禁止模型发现和加载，手动加载仍可用 |
| `license`、`compatibility`、`metadata`、`allowed-tools` | 标准元数据，当前不作为权限或运行控制 |

名称不得以连字符开头或结尾，也不得包含连续连字符。实际加载会重新校验名称、描述及发现名称的一致性。

加载时移除全部前置元数据，将 Markdown 正文交给模型。影响执行的环境要求应写入正文。

## 加载与分支

系统提示词只列可由模型调用的技能名称和描述。工具参数为 `skill({ name: string })`。

首次加载返回：

```xml
<invoked_skill root="skill://review"/>

技能正文
```

每个版本写入宿主可见的分支记录，保存内容哈希、路径、逻辑根、作用域和加载来源。模型加载还记录工具调用 ID。

资源授权取当前分支中每个名称的最新记录。正文去重按来源判断：

- 模型加载：对应工具事务仍在有效上下文中时省略重复正文。
- 手动加载：当前分支记录仍是同一版本时省略重复正文。

压缩或 prune 移除工具事务后，模型再次加载会重新取得正文，已有分支授权仍按加载记录恢复。切换分支后以目标分支记录为准，新会话重新加载。

手动加载以不触发推理的消息写入上下文。技能正文完整读取。

## 资源路径

```text
skill://review
skill://review/references/checklist.md
```

已加载技能的根和后代可供六个文件工具访问。write 和 edit 可以修改技能，默认审批策略要求确认。

解析检查逻辑根与真实路径，拒绝 `..`、空路径段、百分号编码等非法形式，也拒绝越界符号链接。通过普通绝对路径或别名绕过已发现技能目录的授权会被阻止。

技能文件保留逻辑路径与版本观测，后续 edit 仍需满足版本校验。

Bash 可将完整静态参数解析为真实路径：

```bash
python "skill://review/scripts/check.py"
```

动态拼接和内嵌 Shell 脚本中的定位符会被拒绝。命令输出可能包含真实路径。

实现位于 `src/harness/skill-context/`，授权状态由 `state.ts` 从分支记录恢复。
