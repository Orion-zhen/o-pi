# 系统通知

审批请求和正常任务完成可触发系统通知。`src/harness/attention.ts` 将事件转换为会话信息，各前端负责投递。

## 投递条件

GUI 中，只有可见且有焦点的客户端正在查看目标会话时，才抑制该会话的通知。正在查看会话 A 不影响会话 B 的提醒。主动取消和最终助手消息失败时不发送完成通知。

| 前端 | 投递方式 |
| --- | --- |
| TUI | Linux `notify-send`，macOS `osascript`，Windows PowerShell WinRT Toast |
| Desktop | Electron 主进程发送原生通知，点击后打开目标会话 |
| Web | 浏览器 API，需要授权和安全上下文 |

TUI 焦点未知或失焦时发送，通知命令最多执行 5 秒。SSH 中的通知发生在远端电脑。

Web 同浏览器标签页共享投递标识，每个事件选择一个标签页发送。页面关闭后停止接收通知。Desktop 和不同浏览器分别投递。

## 内容与配置

标题为“OPi 需要审批”或“OPi 任务完成”。正文优先使用会话名，未命名时取首条用户消息开头，合并空白后最多保留 80 个 Unicode 码点。审批通知追加工具名。

通知内容可能显示在锁屏上。完成通知请求静音，审批采用系统声音设置，最终表现由平台决定。

设置 `OPI_NO_NOTIFICATIONS=1` 关闭全部通知出口。系统权限、勿扰模式和平台应用身份继续生效。

## 连接与生命周期

GUI 将绘制帧和通知分为两个通道。通知即时投递，不等待绘制确认。关注状态绑定连接，断开后清除，重连后重新上报。

通知失败由投递端处理，任务和审批继续运行。
