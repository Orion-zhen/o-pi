# LSP 协议与增强

## 读取与搜索

`read` 的局部读取和截断结果可以带包围符号与大纲。有效文档符号优先，平面符号作为导航锚点，Tree-sitter 补齐结构。完整读取直接返回正文。

`grep` 在正文扫描时预热相关服务器，随后按文件分析符号。正文零命中时用工作区符号选择有界候选。文档符号、引用、调用层次和定义分别判断能力，失败只影响对应结果。

分析通过调用方的稳定快照加载器读取正文。LSP 与语法结构按声明锚点关联，冲突和歧义保留在内部数据。关系请求与文档同步在同一 URI 队列中完成。

前 4 个 grep 区域各可显示最多 2 个关系位置。每个文件最多 16 次调用点定义请求，额外验证最多 16 个文件。多目标导航带 `?`。完整排序见[文件工具排序](../file-tools/ranking.md)。

## 修改后诊断

`write` 和 `edit` 提交后通知已启动且监视规则匹配的服务器，同一批修改先同步全部文档，再查询诊断。

支持 `diagnosticProvider` 时拉取诊断，否则等待发布。新增错误优先，原有错误标记 existing，基线未知时保留不确定标记。警告按修改范围与新增情况筛选。

可见错误可以附加唯一、已解析的单文件 quickfix 标题。每文件最多请求 3 次，单批提示等待最多 300ms，并受诊断总预算约束。提示仅展示标题，文件修改仍由代理决定。

本次拉取报告中的关联文档最多展示 3 个，与当前文件共用条数预算。同源基线已知时展示新增错误，其他情况标明归因不确定。路径仍经过文件工具访问检查。

诊断超时或失败保留文件修改成功状态。

## 同步与能力

客户端保存初始化能力，只发送支持的请求。文档同步遵循 `Full`、`Incremental` 或 `None`，增量范围使用 UTF-16。`didOpen`、`didClose` 和 `didSave` 按服务器声明发送。

只读分析临时打开文档，请求结束后关闭，缓存按内容版本保留。拉取诊断保存 `resultId`，未更改报告复用快照。发布式诊断记录修订号并丢弃过旧文档版本。

服务器请求支持 `workspace/configuration`、`workspace/workspaceFolders` 和允许的动态注册。动态注册范围为文件监视与配置变更，其他请求返回 `MethodNotFound`。

## 生命周期

`LspManager` 按工作区和服务器持有连接。新会话、恢复和分支保留进程级管理器，重载与退出关闭连接。

每代连接独占传输、请求、取消信号、文档队列和缓存。并发启动共享初始化，单个调用取消只停止自身等待。没有活动请求或通知时开始计算空闲时间。

reload 先阻止新增强，等待已开始的操作链，再在同一截止时间内发送 shutdown、exit 并等待退出，超时后关闭连接或终止子进程。

初始化失败标记 unavailable，ready 后崩溃标记 crashed。修复后执行 `/lsp reload`。状态中的 `last_error` 保留受限的标准错误尾部。

## 实现

`LspManagerRuntime` 管理加载与重载，`LspWorkspace` 管理配置和路由，`LspClientLifecycle` 管理启动与关闭，`LspClientConnection` 管理单代协议，`LspClientDocuments` 管理同步与缓存。
