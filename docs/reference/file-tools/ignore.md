# 忽略规则

忽略规则控制自动发现的可见性，访问拒绝由[受阻路径](path-security.md)控制。

## 优先级

从高到低：

1. 合并配置中的 ignored_path。
2. `.piignore`。
3. `.gitignore`。
4. 内置规则。

同来源中子目录优先，同文件中后面的匹配优先。规则相对所在目录解释，使用字面路径与 `/` 分隔。Git 全局忽略文件和 `.git/info/exclude` 不参与。

## 可见性

`visibility.evaluate` 返回 ignored、prune 和可选 source、rule。ignored 表示软忽略，prune 表示可停止遍历子树。

相关否定规则存在时，求值器保留继续遍历的可能。配置忽略可以直接剪枝。

ls 显示忽略标记，明确读写仍可访问。find、grep 的明确根或 glob 静态目录前缀可以穿过软忽略，后续自动发现继续应用规则。

## 加载

调用绑定有效配置、Git 已跟踪集合和内置规则。目录枚举复用 readdir 快照，处理子项前加载当前目录规则。明确访问文件时，只准备祖先目录链。

并发请求共享目录加载，同次调用的已加载规则保持稳定。后续调用重新读取访问到的规则文件。

规则文件采用 UTF-8，可带 BOM，符号链接形式跳过。读取失败时继续应用其他有效规则，用户取消终止操作。

## Git 与缓存

Git 已跟踪集合通过 `git ls-files -z` 获取。启用绕过时，已跟踪文件只绕过 `.gitignore`，其他来源继续生效。

大小写先取 Git core.ignoreCase，否则使用平台默认。Git 状态按目录、索引和配置文件元数据失效。

grep 每次按当前策略重新发现候选，再读取正文与 AST 缓存。缓存绑定工作区、路径和文件快照，AST 另绑定正文哈希。无关规则变化不会淘汰未变文件。
