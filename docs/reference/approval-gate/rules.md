# 审批规则

## Bash 分析

Tree-sitter 将 Shell 输入拆为简单命令、嵌套替换、静态 `-c` 子脚本和文件写重定向。每个单元保留原文和解包后的有效命令。一次调用只准备一份命令、工作目录和启动环境。审批检查原命令以及 `skill://` 路径替换后的命令，批准后使用同一份快照执行。`/approval-check` 走相同的准备流程，不执行命令。

解析器按执行顺序跟踪赋值、工作目录、有限循环取值、静态函数调用和 EXIT trap。命令替换和进程替换各自继承外层状态。替换内的赋值和目录变化影响同一替换的后续语句，不影响外层。Bash 审批与技能路径解析共用引号和转义解码。

分支合并后，每个变量和工作目录最多保留 8 个候选。`cd ./build` 后的相对路径按成功和失败两种目录检查。`CDPATH` 为空或未设置时，`cd build` 与 `cd ./build` 按相同路径检查。非空时还检查每个搜索目录，相对项基于当前工作目录，不探测目录是否存在。无法确定搜索路径时保留未知候选。任一已知写入目标命中 deny 即拒绝。

程序名或 `-c` 脚本来自有限分支时，解析器逐一检查候选。所有候选都是参数确定的直接调用时，不因分支本身要求审批。管道中的间接调用仍保留动态审批，因为单个候选不能代表整条管道。取值未知或超出分析预算时，不按部分候选放行。

在启动状态已知的非 Windows Bash 中，独立的 `$name` 或 `${name}` 可解析为一个字段，包括程序名、参数和重定向目标。值必须非空，且只含字母、数字等不会触发分词或文件名展开的路径字符。`case "$MODE"` 的选择值确定、模式均为简单字面量或 `*`、每项以 `;;` 结束时，只分析第一个匹配项。Windows Bash 可能转换环境路径，SSH 启动的 Bash 可能读取启动文件，这两种情况不做上述收窄。条件读取的启动值也计入会话记忆限制。`raw-input` 仍匹配完整脚本。

这两项推断从脚本开头和已选中的分支开头生效，可经过简单字面赋值和不改写状态的 `echo`、`:`、`true`、`false`。遇到修改 `IFS`、设置 Shell 选项或其他未建模的前置语句后，不再用启动时的分词和匹配规则排除可能性。

写重定向的父目录已知、文件名含一个数字展开时，解析器保留文件名前后缀，不猜测实际数值。支持 PID、退出状态，以及已知来自 Bash 且未失效的 `RANDOM`、`BASHPID`、`PPID`、`UID` 和 `EUID`。这类目标不能记忆为精确路径。单引号或转义后的 `$` 仍是字面文本。

当前 `HOME` 是已知绝对路径时，未引用的 `~` 和 `~/` 使用该路径展开。无参数 `cd` 的成功分支也使用该路径。`HOME` 未设置时不查询系统账户目录。

已知字符串支持字面前后缀裁剪和 `${name##*/}`。`${name:-default}` 和 `${name-default}` 区分空值、已清除和未知值。默认值可以是单个 `$变量名`，仅在选中默认值时读取。普通变量从工具过滤、注入后的启动环境取初值，不读取其他会话的环境。Shell 自行维护的变量不按普通环境值推断。启动脚本或导入函数使初始状态不确定时保留不透明审批。子 Shell 不直接继承父分析器的变量表。依赖启动值或启动状态未知的请求不提供会话记忆。脚本用独立值覆盖或清除变量后，后续读取不再依赖该变量的启动值。

审批面板只列出分析用到的启动值。请求用到按名称识别的敏感值时，面板默认显示源表达式，不显示展开后的目标。GUI 仅在用户点击“查看敏感值”时读取当前弹窗的明文详情。

`set --` 按原位置参数展开实参，再替换位置参数。解析器保留首个不确定参数之前的字面量、可确定为单个字段的变量、可确定的双引号参数和 `~/` 路径。函数调用不继承调用者的位置参数。在启动状态仍可确定的非 Windows Bash 前缀中，`cd ./dir || exit 1` 只有成功分支能继续执行。紧随其后的 `||` 分支不会生成审批单元。遇到函数遮蔽、退出重定向或 EXIT trap 时仍检查两条分支。

语法错误、超时、资源不可用或复杂度超限时，解析器为完整输入追加 `<opaque>` 单元，已分析的单元仍参与审批。动态命令使用 `<dynamic>`。不透明输入可在当前会话精确记忆。

## 临时范围

临时范围包括有效 `mktemp` 创建的路径，以及宿主进程启动时 `os.tmpdir()` 指定目录的后代。临时根必须是绝对路径，不能是文件系统根。目录名本身不产生豁免。`mktemp` 支持静态模板、`-d`、`--suffix`、`--tmpdir` 和 `-p`。

Windows 按盘符或 UNC 共享解析绝对路径，不把 Bash 的单根路径或盘符相对路径补全到当前盘符。无法确定宿主映射的重定向仍按动态目标审批。

完全位于该范围的重定向、删除、write、edit，以及临时工作区的 `git clean` 和 `git reset --hard` 可跳过 ask。

路径比较不跟随符号链接。临时根本身、规范化后越界的路径、混合目标、可能分词的裸变量、`rmdir -p`、提权和无法确定的控制流无法获得豁免。显式 deny 仍优先。

## 事实与动作

`tools.bash.facts` 按事实 ID 定义分类器和可选动作。字符串分类器使用 `source-unit`，对象形式可以指定：

- `scope`：`raw-input` 匹配完整输入或传给子 Shell 的完整 `-c` 脚本。`source-unit` 匹配命令原文，依赖上下文展开时也检查展开后和解包后的命令。`effective-unit` 只匹配解包后的命令。
- `platform`：按当前进程平台限制。

`combinations` 在多个事实同时出现时升级动作，优先级为 deny、ask、default_action。Bash 的默认 deny 拒绝整次调用，记忆规则和临时范围不能覆盖。

用户覆盖按 ID 递归合并。分类器和组合可设为 false，事实可设 `enabled: false`。配置加载时校验正则和事实引用。

## 路径规则

```json
{
  "name": "system-path-write",
  "tools": ["bash", "write", "edit"],
  "path_globs": ["/etc/**", "/usr/**", "/System/**"],
  "reason": "system path modification"
}
```

规则匹配 write、edit 目标和可静态解析的写重定向。普通命令参数如 `rm /etc/file` 由 Bash 分类器处理。

目标转为使用 `/` 的绝对路径，技能保留 `skill://`。glob 使用 picomatch，`*` 匹配一个路径段，`**` 跨段，数组任一命中即可。缺少 `path_globs` 时只匹配工具名。

## 会话授权

授权只匹配同一工具。Bash 命令匹配请求工作目录和规范化后的完整子命令，文件操作匹配精确路径，私网请求匹配完整 origin。授权只保存在内存中。GUI 回收执行实例时保留当前逻辑会话的授权，新会话和分支不会继承。
