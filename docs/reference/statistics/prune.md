# 上下文裁剪

```text
/prune
/prune force
/prune restore
```

prune 等待代理空闲，处理同时存在工具调用与结果的完整历史事务。裁剪作用于模型上下文，原始消息与会话文件保留。

## 成本判断

普通 prune 比较下一次请求的两种估算成本：保留上下文复用现有缓存，裁剪后复用首个删除点之前的前缀，其余按输入或已观测的缓存写入价格计算。

高置信度下，裁剪成本不超过保留成本的 1.1 倍时执行。低置信度下，只有裁剪明确更便宜时执行。否则保留原状态并通知用户。

估算覆盖已有提示词，下一条用户输入与未来输出不在其中。缓存行为仍由提供方决定。

## 强制与恢复

`force` 跳过成本检查，裁剪当前全部可处理事务。仅含这些调用和思考内容的助手消息一并移除，混有正文的消息保留正文。

`restore` 撤销最近一次可恢复裁剪。若压缩已移除本次需要恢复的任一事务，恢复操作失败并保留当前状态。

裁剪之后新产生的事务不受旧裁剪影响。连续 restore 逐次恢复。

## 状态

操作由 `PruneService` 串行执行。会话分支保存裁剪记录，导航时按目标分支恢复。TUI 展示当前分支最新检查点的聚合摘要。

技能工具事务被裁剪后，再次加载可能重新返回正文，资源授权仍取分支加载记录，见[技能](../skill-context/README.md)。
