# GUI 诊断

## 页面异常

消息区、输入区、左栏、会话信息和工具栏分别隔离渲染异常。设置、功能面板和交互对话框也有独立错误边界。

面板渲染失败时卸载该面板，释放遮罩和焦点锁。设置草稿随卸载丢弃，后台交互请求保留。用户可重新打开面板。

页面保留最近 10 条异常。详情包含诊断编号、时间、异常栈、React 组件栈、会话标识、最近操作、推送批次和浏览器信息，并提供复制入口。

Desktop 将报告写入 `gui-timing.jsonl`，回执显示实际路径、`run` 和环境。Web 报告保留在页面，需要手动复制。渲染进程退出时 Desktop 用原生对话框显示退出原因和日志位置。

报告不主动采集消息、附件和操作参数，异常文本和调用栈可能含路径或上游敏感内容。前端构建保留函数名、组件名和隐藏 source map，调用栈还原需使用同次构建产物。

## 桌面时间线

默认日志位置见[排障指南](../../guides/troubleshooting.md#gui-异常或卡顿)。日志异步写入，达到 2 MiB 后轮转为 `.1`，保留两份，正常退出等待写入完成。

| 事件 | 含义 |
| --- | --- |
| `main_received` | 主进程收到操作，`submittedAt` 为页面提交时间 |
| `backend_received` | SDK 后端收到请求 |
| `user_available` | 后端首次观察到当前会话中的新用户消息 |
| `user_snapshot` | 主进程收到包含用户消息的状态 |
| `renderer_received` | 渲染进程收到推送 |
| `renderer_applied` | 前端解码并通知订阅者后确认 |
| `request_settled` | 操作完成或失败，聊天请求通常对应整轮结束 |
| `gui_error` | 页面或渲染进程异常 |

用 `run`、`generation` 和 `deliveryId` 关联推送，用 `requestId` 关联请求。时间字段为 Unix 毫秒。排查首次发送时，排除用户时间早于本次提交时间的历史重放。

`renderer_applied` 表示前端已应用数据，实际绘制由浏览器继续完成。时钟调整也会影响跨进程时间差，时间线用于缩小调查范围。
